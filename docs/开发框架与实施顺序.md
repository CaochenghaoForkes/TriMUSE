# TriMUSE：TRISO 多物理场有限元程序开发框架与实施顺序

## 一、总体架构

程序命名为 **TriMUSE（TRISO Multiphysics Simulation Engine）**，采用 Python 与 C++/MFEM 分层的混合架构，并通过 pybind11 进行数据传递。框架从两个层次设计：

1. 语言分工：明确 Python 层与 C++ 层的职责边界。
2. 功能分类：按照输入、几何网格、物理场、材料、耦合、求解和后处理划分模块。

基本原则是：Python 负责“描述和组织问题”，C++ 负责“离散并求解问题”。

## 二、语言分工

### 2.1 Python 层

Python 层主要负责：

- 读取、检查和组织多张 XML 输入文件；
- 定义几何、材料区域、边界和载荷；
- 调用 Gmsh 建立几何并生成网格；
- 定义热传导、核素扩散和力学问题；
- 定义物理场之间的依赖关系、求解顺序和耦合策略；
- 调用 C++ 有限元内核并传递计算配置；
- 组织时间步、参数扫描和算例批处理；
- 读取计算结果并进行后处理

Python 层不负责单元积分、总体矩阵装配和大规模线性方程组求解。

### 2.2 C++/MFEM 层

C++ 层主要负责：

- 建立有限元空间及各物理场自由度；
- 定义试函数空间、权函数空间和边界自由度；
- 完成单元积分及总体方程装配；
- 处理本质边界条件和自然边界条件；
- 调用线性、非线性和特征值求解器；
- 保存积分点和单元材料状态；
- 更新温度相关、浓度相关和历史相关的材料参数；
- 执行每个时间步或耦合迭代中的实际数值求解；
- 向 Python 返回场变量、收敛信息和必要的派生量

### 2.3 耦合职责的边界

耦合分为“定义”和“执行”两部分：

- Python 定义有哪些物理场、场之间传递哪些量、采用何种求解顺序以及何时终止耦合迭代；
- C++ 完成场数据在有限元空间中的计算、材料状态更新、方程装配和单次求解；
- 对性能敏感的强耦合迭代，可以在后续阶段下沉到 C++，但对 Python 暴露统一接口

## 三、功能模块

以下九项是同一项目内部相互独立的逻辑子模块，不拆成九个需要分别安装和发布的软件包。Python 侧建立一个 `trimuse` 包并按功能设置子包；C++ 侧建立一个 `trimuse_core` 库并按功能设置命名空间；两者通过一个 pybind11 接口层连接。

### 3.1 输入与配置模块（Python）

#### 3.1.1 模块职责

输入模块负责读取多张 XML，完成路径、单位、数据类型和相互关系检查，并将文本输入转换为程序内部统一的配置对象。它只解释用户输入，不直接创建 Gmsh、MFEM 或求解器对象。

基本数据流为：

$$
\text{XML 文件}
\longrightarrow
\text{XML 读取器}
\longrightarrow
\text{配置对象}
\longrightarrow
\text{问题定义模块}.
$$

#### 3.1.2 XML 文件分类

- 总调度 XML：算例名称、所用子配置文件、本次运行的目标阶段和输出位置；
- 几何与网格 XML：空间维数、几何类型、尺寸、材料区域、网格尺寸和外部网格路径；
- 热工 XML：稳态或瞬态类型、导热参数、热源、初始条件和边界条件；
- 扩散 XML：稳态或瞬态类型、扩散系数、源项、初始条件和边界条件；
- 力学 XML：静力或瞬态类型、弹性、热膨胀、蠕变、肿胀、载荷和约束；
- 材料 XML：材料模型、模型参数以及参数对温度、浓度、时间等变量的依赖关系；
- 单元与求解器 XML：有限元阶次、时间离散、线性与非线性求解器及收敛条件；
- 输出 XML：输出变量、输出时间和文件格式。

总调度 XML 只保存算例级信息和其他 XML 的路径，不重复保存各物理场的具体参数。程序的顶层执行顺序固定为“输入检查、几何网格准备、问题构建、求解、后处理”，不允许用户任意重排；总调度 XML 只通过 `execution` 指定本次运行到哪一阶段为止。热、扩散和力学之间的耦合次序属于耦合模块配置，不属于顶层执行顺序。

#### 3.1.3 内部组成

- 总调度读取器：读取总调度 XML，并定位本算例使用的其他配置文件；
- 专用 XML 读取器：分别读取几何网格、热工、扩散、力学、材料、求解器和输出配置；
- 配置数据对象：保存读取后的结构化数据，供后续模块使用；
- 单位处理器：把输入单位统一换算为程序内部单位；
- 路径解析器：以总调度 XML 或相应子 XML 所在目录为基准解析相对路径；
- 输入校验器：检查必填项、取值范围、名称唯一性以及不同 XML 之间的引用关系；
- 错误报告器：指出出错文件、XML 节点、参数名称和错误原因。

#### 3.1.4 配置对象

输入模块最终应形成以下顶层配置对象：

- `CaseConfig`：整个算例的入口和各子配置的集合；
- `GeometryMeshConfig`：空间维数、几何类型、区域、边界和网格参数；
- `ThermalConfig`：热传导分析类型、初边值条件和源项；
- `DiffusionConfig`：扩散分析类型、初边值条件和源项；
- `MechanicsConfig`：力学分析类型、约束、载荷和本征应变设置；
- `MaterialConfig`：材料模型名称、参数和适用区域；
- `NumericsConfig`：单元阶次、时间离散和求解器设置；
- `OutputConfig`：输出变量、频率、位置和格式。

这些名称表示架构中的数据职责，当前阶段不确定具体类和代码实现。

#### 3.1.5 输入检查层次

输入检查分为三层：

1. 单文件检查：XML 格式正确，必填参数存在，数值、单位和名称合法；
2. 跨文件检查：材料名、区域名、边界名和物理场引用能够对应；
3. 运行前检查：问题维数与网格维数一致，瞬态问题具有时间设置，所选物理场具有完整初边值条件。

### 3.2 几何与网格模块（Python）

#### 3.2.1 模块职责

几何与网格模块接收 `GeometryMeshConfig`，负责建立或导入计算域、划分材料区域、标记边界并生成 MFEM 可以读取的网格文件。

基本数据流为：

$$
\text{GeometryMeshConfig}
\longrightarrow
\text{几何构造或外部导入}
\longrightarrow
\text{物理组标记}
\longrightarrow
\text{网格生成与检查}
\longrightarrow
\text{网格文件和 MeshInfo}.
$$

该模块只负责几何区域和边界的名称及编号，不负责决定区域采用什么材料模型，也不负责施加具体边界条件。

#### 3.2.2 内部组成

- 几何与网格管理器：根据配置选择几何构造器、外部网格导入器和网格生成流程；
- Gmsh 接口层：统一封装 Gmsh Python API 的初始化、模型操作、网格生成和文件输出；
- 几何构造器：一种几何类型对应一个构造器；
- 外部网格导入器：读取用户直接提供的 `.msh` 文件；
- 区域与边界注册器：根据用户提供的名称，统一生成并管理体区域和边界物理组的正整数编号；
- 网格尺寸策略：管理全局单元边长范围、各区域目标单元边长、界面局部加密和尺寸渐变；
- 网格生成器：设置网格维数、单元类型和阶次并调用 Gmsh 划分网格；
- 网格检查器：检查维数、区域、边界、单元数量和基本网格质量；
- 网格输出器：输出 `.msh` 及网格摘要信息。

#### 3.2.3 几何类型

- 理想同心多层球体几何；
- 由二维 $\phi$-$\theta$ 分布及厚度分布构造的非理想多层颗粒几何；
- 外部 `.msh` 网格直接导入；
- 根据断层扫描等外部数据重建几何的预留接口；
- 其他一维、二维和三维基准几何的预留接口。

不同几何构造器应产生相同类型的输出，使后续物理场模块不需要知道网格来自理想几何、测量数据还是外部文件。

几何类型采用“构造器选择属性 + 同名参数子节点”表达。例如，`geometry` 的 `source="ideal_multilayer_sphere"` 选择理想多层球构造器，该构造器的全部特有参数放在同名的 `ideal_multilayer_sphere` 子节点内。输入模块应检查两者名称完全一致。以后增加其他几何时，使用新的 `source` 名称及其同名参数子节点。

#### 3.2.4 维数与模型类型

- 几何模块根据输入建立一维、二维或三维几何；
- 对于程序生成的网格，输入配置决定网格维数；
- 对于外部网格，程序读取其拓扑维数和所处空间维数，并与输入配置核对；
- 二维有限元模型还需由问题定义模块说明采用平面应力、平面应变或轴对称形式。

几何的参数化维数和最终有限元问题的维数需要区分。例如 $\phi$-$\theta$ 厚度分布是描述三维颗粒表面的参数化方法，最终仍可生成三维体网格。

Gmsh 和 MFEM 中的网格结点使用欧氏空间中的笛卡尔坐标表示，因此几何输入不要求用户选择 `coordinate_system`。轴对称等选项表示控制方程和弱形式的模型类型，应在问题定义或相应物理场配置中设置，而不是在几何网格中设置。

#### 3.2.5 区域与边界编号

Gmsh 物理组作为几何与有限元内核之间的数据契约：

- 用户为三维体、二维面或一维线区域提供唯一的区域名称；
- 用户为外边界和材料界面提供唯一的边界名称；
- 对于程序内置几何，TriMUSE 根据固定规则为这些名称分配正整数物理组编号；
- 对于外部 `.msh` 网格，TriMUSE 读取其中已有的物理组名称和编号；
- 区域编号供 MFEM 识别单元所属区域；
- 边界编号供后续模块施加热学、扩散和力学边界条件；
- 名称是用户输入以及不同 XML 之间引用的主要标识，编号是 Gmsh 与 MFEM 之间的内部标识；
- 几何模块保证名称与编号的对应关系稳定、唯一，但不解释相应材料或边界条件的物理含义。

需要区分 Gmsh 几何实体编号与物理组编号：几何实体编号由 Gmsh 建模过程产生，不作为稳定接口；物理组编号由 TriMUSE 生成或从外部网格读取，并通过名称与用户输入对应。

#### 3.2.6 网格输出

几何与网格模块输出两类结果：

1. `.msh` 网格文件：保存节点、单元、区域属性和边界属性；
2. `MeshInfo`：保存网格路径、维数、区域和边界名称与编号、单元类型、阶次、数量和质量摘要。

MFEM 读取 `.msh` 后应得到与 `MeshInfo` 一致的区域属性和边界属性。

网格配置分为两层：单元类型、几何阶次和尺寸控制属于通用网格要求；三维划分算法、优化方法、MSH 版本和二进制选项属于 Gmsh 专用参数，放在 `gmsh` 子节点中。以后更换网格引擎时，可以尽量保留通用要求，只替换引擎专用配置。这里的几何阶次描述网格单元的几何映射，不是物理场有限元空间的插值阶次；后者由单元与求解器配置管理。

Gmsh 专用设置中，`algorithm_3d` 选择三维体网格生成算法，`optimizer` 选择网格生成后的质量优化方法，`msh_version` 选择输出文件版本，`binary` 选择二进制或文本存储。`optimizer="none"` 表示不优化，`optimizer="gmsh"` 表示采用 Gmsh 默认四面体优化器；后续可扩展 `netgen` 等选项。

尺寸控制中的 `edge_length` 表示目标网格单元边长，并继承模型声明的长度单位。它不是单元数量，也不是颗粒半径。对于四面体网格，实际边长不一定严格等于目标值，网格生成器会结合区域尺寸、几何曲率、界面和尺寸渐变生成接近该尺度的网格。

#### 3.2.7 第一阶段实现边界

第一阶段只考虑：

- 三维理想同心多层球体；
- 一阶四面体网格；
- 每层独立的体区域物理组；
- 各材料界面及最外表面的边界物理组；
- 全局网格尺寸和各层局部网格尺寸；
- Gmsh 4.1 格式 `.msh` 输出；
- 外部 `.msh` 文件的基本读取与维数、物理组检查。

非理想厚度分布几何、断层扫描重建、高阶单元和复杂网格优化在这一链路稳定后再加入。

### 3.3 问题定义模块（Python）

把配置对象、网格区域、材料、边界条件和物理场组合为一个完整计算问题，并检查它们之间的一致性。稳态、瞬态或准静态作为各物理场自身的属性。

### 3.4 材料模块（Python 配置，C++ 计算）

Python 选择材料模型并组织模型参数；C++ 在积分点计算热学、扩散、弹性和非弹性性质，并保存、更新材料历史状态。

### 3.5 物理场模块（C++）

建立热传导、核素扩散和力学有限元空间，处理相应初边值条件，并完成方程装配与单次物理场求解。

### 3.6 耦合与时间推进模块（Python 调度，C++ 执行）

Python 定义时间步、物理场求解顺序、数据传递和耦合收敛条件；C++ 执行每个物理场求解和材料状态更新。第一阶段采用分区顺序耦合。

### 3.7 数值求解模块（C++）

统一管理 MFEM、Hypre 和 PETSc 求解器后端，以及线性求解器、预条件器、非线性迭代、时间积分和收敛判据。

### 3.8 状态与重启动模块（C++ 保存状态，Python 管理文件）

保存当前及历史场变量、积分点材料状态、时间步和收敛状态，并支持检查点和中断后的重启动。

### 3.9 输出与后处理模块（C++ 输出场数据，Python 后处理）

由 C++ 输出网格场、材料状态和收敛信息；由 Python 完成结果读取、统计、绘图、ParaView 文件管理及与 BISON 结果的比较。

## 四、程序包总体组织

计划中的程序结构如下。该结构仅表示模块边界，当前阶段不创建对应代码目录。

```text
TriMUSE/
├── main.py                         # Python 程序入口
├── trimuse/                        # Python 主包
│   ├── input/                      # 输入与配置模块
│   ├── geometry/                   # 几何与网格模块
│   ├── problem/                    # 问题定义模块
│   ├── coupling/                   # 耦合与时间推进调度
│   └── postprocess/                # 输出管理与后处理
├── cpp/                            # C++ 有限元核心库
│   ├── materials/                  # 材料模型与积分点状态
│   ├── physics/                    # 热、扩散和力学物理场
│   ├── solvers/                    # MFEM、Hypre、PETSc 求解器
│   ├── state/                      # 计算状态与重启动
│   └── output/                     # C++ 场结果输出
├── bindings/                       # pybind11 接口层
├── cases/                          # 算例 XML、网格和结果
└── docs/                           # 架构和使用说明
```

九个功能模块在职责上相互独立，但共享同一个 Python 包和同一个 C++ 核心库，不作为九个独立项目分别安装。

## 五、第一步开发范围

第一步只打通输入模块和几何与网格模块的一部分：

1. 总调度 XML 能够引用几何与网格 XML；
2. 输入模块把几何与网格 XML 转换成 `GeometryMeshConfig`；
3. 输入模块完成路径、单位、维数、半径、区域名称和边界名称检查；
4. 几何模块根据配置建立三维理想同心多层球；
5. 为每层体区域、每个材料界面和最外表面建立稳定的 Gmsh 物理组；
6. 生成一阶四面体 `.msh` 网格和 `MeshInfo`；
7. 能够导入外部 `.msh` 并检查维数及物理组。

这一阶段的终点是得到一份区域和边界属性完整、后续可由 MFEM 读取的网格；暂不进入有限元空间、材料模型和物理场求解。
